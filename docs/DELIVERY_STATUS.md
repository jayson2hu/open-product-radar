## 上线前需要完成的真实配置与工作

1. GitHub OAuth、管理员公开身份、HTTPS 域名与实际服务器；验证真实登录与权限。
2. 正式来源使用范围核查，批准后持续采集；完成真实产品/套餐证据、至少三份研究结论；积累有效 24h / 7d 基准。
3. 真实邮件供应商与发件域名，验证收件、退订和投诉；当前只使用 GitHub 公开资料返回的邮箱，无地址时站内摘要仍可用。
4. Docker 目标环境、持久存储、受控异地备份、最新删除台账和正式恢复演练。
5. 试点用户招募、访谈、真实任务实测、人工交付工时、真实支付退款续费。没有任何虚构经营结果。

## 明确未完成的功能

- 独立的问题/反馈实体、HN 与其他来源、自动网站和价格变化监控。
- 自动 AI 研究、模型质量评估和提示词版本；当前保留结构化人工判断，不伪装模型已经运行。
- 候选绑定特定版本/套餐 ID、完整事实版本历史、可撤销实体合并和高级全文检索。
- 自动支付与退款、自动权益限制、套餐额度；当前订单仅为人工核验与服务期限台账。
- 按具体操作细分的自动来源权限矩阵、完整账号邮件验证流程、游标分页与正式 PostgreSQL 迁移。
- 团队协作、更多外部分发渠道、SEO 服务端渲染与开放社区。

这些差距已与原需求分开记录。前端构建、测试和演示站通过，不等于上述真实上线和商业验证工作已经完成。

## 接下来的开发顺序

第一批真实试点：配置身份/来源，完成真实证据和三份样例，持续两周期观察；解决实际使用中阻断判断的缺口。

进入小团队试用：增加特定版本候选、事实修订历史、问题跟踪、细粒度来源权限与正式邮箱验证；按实测决定 PostgreSQL 迁移。

确认持续价值后：根据付费反馈完善权益和支付，再考虑更多来源与团队功能；不以实现更多栏目代替验证用户是否回来。
