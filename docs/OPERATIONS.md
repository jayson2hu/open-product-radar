# 运营与交付流程

## 每日

检查来源最后成功时间、失败原因和任务重试；复核新增事件的实体、版本与证据；发布少量影响任务的变化；处理纠错；检查摘要只包含已核查的新事件。没有变化不凑数；来源失败要明确告知不完整。

事件模板：发生什么 / 关联版本和部署 / 影响什么任务 / 证据及核查时间 / 未知项 / 建议复查动作。比较每项给出符合、受限、不符合或未知，附适用范围。

## 每周

复核一个专题、检查高关注事实是否过期、访谈活跃与流失用户、合并同一事件的多份证据、记录共享编辑和个别支持工时。跟踪选型期与采用后使用差异。

## 每月

复核来源权限、检查备份恢复与删除传播、对照实际收入退款续费和总成本、公布重要更正、决定维持或缩小范围。没有付费和续费证据前不扩大付费获客。

## 发布与纠错

待审核事实不能通过前端标签改为已确认。编辑查看原始出处后记录理由，再发布。重要错误应撤回或更正，保存版本和审计；只有经过授权的外发通道才能发送更正邮件。作者资料也进入同一审核标准，付费合作不得影响排名与事实。

## 用户资料

任务、关注原因、笔记默认私有。用户可导出并删除个人资料。不要把私人研究投入公开推荐或模型服务。备份按实际经营地区制定保留规则，恢复前再次应用删除清单。

## 权限

普通用户仅操作自己数据；编辑负责核查；管理员控制来源、预算和经营记录。演示管理员仅用于本地样例，不能作为正式账号管理方式。没有任何自动对外招募或群发任务。
