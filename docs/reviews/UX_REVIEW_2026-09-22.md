# 用户体验审查与修复记录

日期：2026-09-22。范围：`src/` 前端及本记录；不修改数据库、采集任务、Git 或发布配置。

## 设计与实施原则

遵循已阅读的 frontend-design 技能。保留现有研究工作台的布局与视觉，不进行大范围换肤。

- 颜色沿用：背景 `#f8f9fc`、正文 `#252d3b`、辅助文字 `#64748b`、操作色 `#5a54d6`、已确认结果 `#248668`、待核查提示 `#897040`。
- 字体沿用现有 DM Sans 与中文无衬线字体；以正文层级、完整句子和可见说明解释数据，不依赖悬浮提示。
- 布局保持左对齐，在已有列表前增加精简的“总量与增长”说明；不增加无意义的大卡片、编号、动画或新导航。
- 结构意图：`采集结果 → 当前总量与增长的区别 → 明确的浏览顺序 → 项目行 → 证据与下一步`。
- 自检：榜单编号只有真实排名才有意义；当前列表中移除装饰编号。未知增长和没有产品档案应给出原因与下一步，不能用统一“空”状态掩盖。

## 初查证据与影响

| 问题 | 代码证据 | 用户影响 | 处理方向 |
| --- | --- | --- | --- |
| 增长状态只写“历史不足” | `RepositoryTable`、`EntityDetail`、`Method` 使用简短术语 | 容易误认为采集失败，或以为过一天必然自动更新 | 统一解释总量、早期记录、再次采集与持续调度 |
| 没有可比增长仍显示净变化排序及序号 | `Discover` 的排序说明固定；`RepositoryTable` 渲染 `repo-rank` | 把按名称列出的项目误认成增长榜 | 使用 API 的实际排序口径，移除伪排名序号 |
| 产品/事件为空时缺少背景 | 产品面板和目录只有“暂无变化”等统一文案 | 已采集仓库与待审核版本的成果不可见 | 用公开内容库存计数区分仓库、产品档案、已发布事件与待审核版本 |
| 正式环境登录入口直接进入 OAuth | `Login` 的非演示分支无条件链接 `/auth/github` | 未配置登录时跳入 503 | 根据 `/session.capabilities.auth` 显示可用登录或公开浏览说明 |
| 模态窗口与手机侧栏焦点不完整 | 模态初始焦点在容器；侧栏没有键盘焦点约束 | 键盘可能离开弹层或难以关闭导航 | 初始焦点、Tab 闭环、Escape、返回焦点、导航展开状态 |

## 已落实的修改

### 增长数据的解释

- 新增 `src/presentation.js`，统一列表、详情和方法页的增长状态解释。
- 已有总量但缺少早期记录时，列表显示“待对比 / 缺少早期记录”，并在列表前直接说明：当前 Stars 是累计数，最近 24 小时或 7 天的净变化还需要对应时间前的有效记录。说明在手机上同样可见，不依赖悬浮提示。
- 详情分别解释 24 小时和 7 天的情况；“暂无总量”“待对比”“暂不能比”区分没有记录、缺少早期记录和现有记录条件不适合比较。
- 7 天状态优先使用自身的 `trend_7d.status`；该字段缺失而 `delta_7d` 有有效数值时，保留有效的 7 天比较，不让 24 小时状态错误覆盖它。
- 来源未启用持续采集时，明确说明仅等待一天或一周不会自动生成增长，需要后续实际采集。来源受阻、运行状态未确认也有独立说明，不承诺自动更新。
- 手机项目行补充当前 Star 总量，避免只看到“待对比”而误认整个项目没有数据。
- 方法页增加明确标注为示例的 `1,030 − 1,000 = +30` 说明；该示例不作为任何项目的实测结果。

### 浏览顺序与空状态

- 列表不再显示装饰性的项目序号，避免暗示未经证明的名次。
- 排序说明读取接口 `sort.effective`。没有可比增长时展示“项目名称 / 产品名称 · 非增长排名”；手机筛选区同样显示顺序说明。
- 产品目录和产品变化空态读取 `content_status`，区分已收录仓库、尚未建立产品档案、已发布事件和待审核版本记录。
- 有待审核版本时仅展示公开数量，不展示草稿正文，也不把仓库版本自动解释成产品变化。零个已发布事件不再被表述为项目没有更新。
- 详情近期变化为空时，使用当前实体的待审核版本数量解释，并提供原始发布来源入口。
- 产品变化独立请求失败时，展示请求错误与重试入口，不以普通空状态掩盖加载失败。

### 登录、权限与交互

- 登录入口使用 `/session.capabilities.auth`。正式环境未开放登录时显示“登录说明”和可继续浏览的说明，不生成必然失败的 OAuth 跳转链接。
- 保留显式进入独立演示工作区的操作；不会因为正式环境未配置登录就自动切换到演示账户。
- 模态窗口打开时聚焦可操作控件；Tab / Shift+Tab 只在最上层窗口内循环，Escape 关闭最上层窗口，关闭后返回仍存在的原控件。
- 手机侧栏增加关闭按钮、展开状态、键盘焦点约束、Escape 和焦点返回；侧栏打开时主内容不可交互，避免键盘跳入背景。
- 增加“跳到页面内容”入口；导航标明当前页，时间段与类型筛选标明选中状态。
- 按钮的忙碌状态不会被后传入的属性覆盖，避免保存期间再次点击。
- 对异常编码的页面链接（例如 `#entity/%`）安全处理，显示无效链接说明和“返回项目与产品”入口，不让解码异常导致整页空白。
- 编辑角色不显示“成本与试点”，且来源启停与证据删除入口禁用。前端限制仅改善体验，真正的授权仍由服务端强制执行。

### 修改文件

- `src/presentation.js`：独立、可测试的增长、调度、登录、排序、空状态与链接解码逻辑。
- `src/main.jsx`：接入上述说明和能力字段，修复焦点、导航与空状态。
- `src/styles.css`：局部说明、增长状态和手机可读性样式；延续原有视觉。

- 新增展示逻辑对应 `tests/presentation.test.mjs`；完整浏览器流程对应 `tests/e2e.mjs`，本地真实数据复核对应 `scripts/verify-local-collection.py`。最终集成执行结果以项目验收记录为准，不将此次受子进程限制、随后中断的独立测试尝试记为通过。
- 最终集成已补齐一般 404 的恢复入口、任务重试权限控件和“最近观察时间”排序文案；构建、10 项浏览器流程及 12 项真实页面检查通过。真实页检查拦截使用埋点，未触发采集或修改真实资料。
- 后端提供登录能力、内容库存、实际排序和实体相关来源状态；前端不会凭缺失字段推断采集成功、草稿已发布或持续调度已运行。
- 未配置真实 OAuth 的环境可以公开浏览，但不能因此宣称正式账户登录、私人数据保存已经在真实环境验收。相关流程仍需在配置完成后验证。

- 版本草稿仍须审核；产品档案仍需按证据建档。准确的空状态不等于这些内容已经补齐。
- 此次完成代码与自动化可验证性改进；尚未开展首批真实用户的理解度测试。应观察用户能否独立解释“当前总量 / 待对比 / 尚未启用持续采集”，并检验手机阅读与辅助技术实际体验。
